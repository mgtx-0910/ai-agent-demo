# 2026-08-13

## cron-job-tool 修复 flatMap 报错

- 现象：`TypeError: message.content.flatMap is not a function`，堆栈在 `@langchain/openai/dist/converters/completions.js` 的 `convertMessagesToCompletionsMessageParams`（`typeof message.content === "string" ? ... : message.content.flatMap(...)`）。
- 根因：DeepSeek 在纯工具调用（无文本）时 AIMessage.content 为 null，转换器对 null 走 else 分支调 `null.flatMap` 崩溃。
- 修复：`src/ai/job-agent.service.ts` 的 `runJob` 循环中，在 `messages.push(aiMessage)` 之前把 null content 归一化为空字符串（`ai.service.ts` 的 runChain / runChainStream 之前已有同样处理，JobAgentService 遗漏了）。

## 补充：flatMap 报错的真正根因

- 打印 messages 后发现，`time_now` 工具的 ToolMessage.content 是**对象** `{iso, timestamp}` 而非字符串，其他工具（db_users_crud/send_mail/cron_job/web_search）都返回字符串。
- LangChain 会把工具函数返回值原样放进 ToolMessage.content，不自动 stringify。转换器 `convertMessagesToCompletionsMessageParams` 里 `typeof content === "string" ? content : content.flatMap(...)`，对象没有 flatMap 就抛 `content.flatMap is not a function`。之前 SELECT User 那次的报错也是这条 time_now 对象消息触发的（不只是 null content）。
- 修复：`src/tool/time-now-tool.service.ts` 的 fn 改为返回 `JSON.stringify({iso, timestamp})` 字符串。
- 教训：LangChain 工具函数必须返回字符串（或 string[]），不能返回对象，否则 ToolMessage.content 为非字符串会在下一轮传给 OpenAI 兼容转换器时崩。

- 现象：`src/job/job.service.ts:307` 报 `找不到名称"bethis"` + 两个 eslint `no-unsafe-*` 错误。
