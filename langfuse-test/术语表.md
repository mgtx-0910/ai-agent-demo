# Langfuse 名词表 —— 从 Trace 到评测

本文把「追踪」和「评测」两层里最容易混的名词按顺序理一遍，每条都对应本项目的具体代码位置。

---

## 0. 一条主线

```
你的代码             LangChain                   @langfuse/langchain        @langfuse/otel          Langfuse 服务端
agent.invoke()  →   每个生命周期节点触发回调  →  CallbackHandler 开 span  →  SpanProcessor 导出  →  Traces / Scores
```

关键结论：**Langfuse 不监听也不代理你的模型请求**。是 LangChain 在关键时机主动回调，`CallbackHandler` 再用 OTEL API 开 span，最后由 `LangfuseSpanProcessor` 批量发到服务端。

---

## 1. 观测层（Tracing）

| 名词 | 含义 | 本项目对应物 |
| --- | --- | --- |
| **Trace** | 一次完整请求的调用树（根节点），有唯一 `traceId` | 一次 `agent.invoke(...)` |
| **Span** | 树里的一个节点：一段**有起止时间**的操作 | Agent 图节点、`get_weather` / `calculate` 调用 |
| **Generation** | 特殊 Span：一次 LLM 调用，额外记 prompt / completion / token | 每轮模型推理 |
| **Session** | 多条 Trace 的分组（会话 / 批次） | demo 用 `deepagents-demo`；评测用 `eval-<dataset>` |
| **Observation** | Langfuse UI 里对 Span / Generation / Event 的统称 | 时间线里的每个条目 |
| **OTEL** | OpenTelemetry，追踪数据的标准协议与 SDK | `@opentelemetry/sdk-node` |
| **SpanProcessor** | 收集 span 并导出的组件，决定「发到哪、什么时候发」 | `LangfuseSpanProcessor`，`src/instrumentation.mjs` |
| **CallbackHandler** | LangChain 回调 → Langfuse span 的桥，负责「产生 span」 | `new CallbackHandler({...})` |
| **Context 传播** | 靠 `AsyncLocalStorage` 把父子关系串起来，无需手写 `parentId` | `invoke` 内部天然嵌套 |
| **`last_trace_id`** | Handler 运行中回填的 trace id，用于在 UI 精确定位 | `src/index.mjs` 末尾打印 |

### 常见误解：Span 不是 HTML 的 `<span>`

| | HTML `<span>` | Trace 的 Span |
| --- | --- | --- |
| 本质 | 行内容器元素 | 带起止时间的操作记录 |
| 维度 | 空间：一段文字 | 时间：一个区间 |
| 有无语义 | 无 | 有，必须说明「做了什么」 |

词源相同（「一段跨度」），含义毫无关系：HTML 框住一段字，span 框住一段时间。

一条 span 的实质内容：

```json
{
  "traceId": "8f3c1d2e...",
  "spanId": "a1b2...",
  "parentSpanId": "f9e8...",
  "name": "get_weather",
  "startTime": 1699999999.120,
  "endTime": 1699999999.123,
  "attributes": { "input": { "city": "Shanghai" }, "output": "31°C，闷热多云" },
  "status": "OK"
}
```

## 2. 「一次完整的请求」到底指什么

在本项目里 = **一次 `agent.invoke(...)` 从进入到返回（或抛错）的全过程**（`src/index.mjs:55`）。

三个层次别混：

| 层次 | 边界 | 对应概念 |
| --- | --- | --- |
| 一次 HTTP 往返 | 请求发出 → 响应收完 | 一个 **Generation** |
| 一次 Agent 运行 | `invoke()` 进入 → 返回 | 一条 **Trace** |
| 一次多轮对话 | 用户多次提问 | 一个 **Session** |

一次 trace 的实际形状：

```
invoke() 开始 ─────────────────────────────────────── invoke() 返回
  ├─ Generation 1  模型: 要调 get_weather
  │   └─ Tool span  get_weather("Shanghai") → "31°C，闷热多云"
  ├─ Generation 2  模型: 还要查东京
  │   └─ Tool span  get_weather("Tokyo") → "28°C，晴"
  ├─ Generation 3  模型: 调 calculate 算 31+28
  │   └─ Tool span  calculate(31, 28) → "59"
  └─ Generation 4  模型: 直接回答，不再要工具  ← 循环在此自然结束
```

**1 条 trace，4 个 generation，3 个 tool span。**

### 为什么「模型不再返回 tool 就结束」不严谨

那是**框架内部的循环终止条件**，不是 trace 的边界：

1. **零工具也成立** — 问「你好」，只有 1 个 generation、0 个 tool span，仍是一条完整 trace。
2. **工具数不定** — 上面 3 个 tool span 全在同一条 trace 里，不是每个工具一次请求。
3. **被强制中断也算** — `recursionLimit: 30` 耗尽抛 `GraphRecursionError`，trace 照样存在，只是 `status` 变 ERROR（排查死循环的关键线索）。
4. **会话 ≠ trace** — 同 `sessionId` 下跑 5 次 = 5 条 trace、1 个 session。

严格说，底层 LangGraph 每轮检查最后一条 AIMessage 有没有 `tool_calls`：有 → 路由到工具节点继续循环；没有 → 走到 `END`。trace 包裹的是**整个图的执行**，而不是最后那一跳。

## 3. 评测层（Evaluation）

| 名词 | 含义 | 本项目对应 |
| --- | --- | --- |
| **Dataset** | 评测集，是「身份标识」，同名继续追加、改名另起一套 | `deepagents-eval` |
| **Dataset Item** | 一条用例：`input` / `expectedOutput` / `metadata` | `weather-shanghai`、`calculate-sum` 等 4 条 |
| **Task** | 被测函数：吃 item → 吐 output | `runAgentTask`（`src/evaluate.mjs`） |
| **Evaluator** | 打分器：拿 item 上下文算分 | `keywordHitEvaluator`、`nonEmptyEvaluator` |
| **Item-level 评分** | 每条用例各打一次 | `keyword_hit`、`non_empty` |
| **Run-level 评分** | 拿整轮所有 item 的结果聚合成一个总分 | `avg_keyword_hit` |
| **Experiment / Run** | 在某个 Dataset 上跑一次「task + evaluators」 | 每次 `npm run eval` 生成一条 |
| **runName** | Run 的显示名，用时间戳保证每次独立、便于横向对比 | `run-2026-...` |
| **Score** | 一条具体分数记录：`name` / `value` / `comment` | `{ name: "keyword_hit", value: 1 }` |
| **maxConcurrency** | 并发度，本项目取 1（串行，输出干净、trace 不打乱） | `runExperiment({ maxConcurrency: 1 })` |

### 一条用例的完整闭环

```
Dataset Item  →  task(item)  →  output  →  evaluators 打分  →  Score 挂在 item 上
                     │
                     └─ 同时产生一条 trace（带 traceMetadata.itemId）
```

`traceMetadata` 里挂了 `dataset` / `itemId` / `case`，所以在 UI 里能按「哪条用例」过滤 trace —— **分数不理想时，点开的那条 trace 就是这个样本的完整现场**。

### 确定性 evaluator vs LLM-as-Judge

本项目用确定性断言（关键词命中、非空），因为答案可枚举（31 / 28 / 59）：便宜、秒级、可复现、零额外依赖。开放式问答才需要 LLM 评委，可接 `createEvaluatorFromAutoevals` + autoevals。

## 4. 两条互不相干的通道

| 通道 | 传什么 | 谁负责 | 收尾 |
| --- | --- | --- | --- |
| **OTEL 通道** | Trace / Span / Generation | `instrumentation.mjs` + `CallbackHandler` | `shutdownTracing()`（`forceFlush` + `sdk.shutdown`） |
| **管理 API 通道** | Dataset / Dataset Item / Score | `@langfuse/client`（`LangfuseClient`） | `langfuse.flush()` |

两者都要收尾，漏一个就丢一半数据。另有两个「空白且不报错」的坑：

1. `import "./instrumentation.mjs"` 不是第一行 → 管道建晚了，早期 span 丢失。
2. 忘了 `callbacks: [handler]` → 管道通着，但没人开 span，同样空白。

## 5. 一页速查

```
Trace        一次 invoke 的整棵树（根节点，有 traceId）
Span         树上一个带起止时间的操作节点（≠ HTML 的 span）
Generation   Span 的一种：一次 LLM 调用（含 prompt / completion / token）
Session      多条 Trace 的分组（demo 用固定 id，评测用 eval-<dataset>）
Dataset      评测集；Item 是用例；Task 是被测函数
Evaluator    item 级打分器；runEvaluator 汇总整轮成一个总分
Experiment   在 Dataset 上跑一轮 task+evaluator = 一条 Run（runName 区分）
Score        name + value + comment 的分数记录，挂在 item / run 上
```
